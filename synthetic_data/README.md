# synthetic_data.jsonl

Synthetic sensor data for **PS26025 — Wireless Surface Mesh Network for Real-Time Mine Subsidence Detection** (SIH 2026).

Generated by `generate_synthetic_data.py`. Used to build and test the backend, ML, and dashboard layers in parallel, before real hardware data is available.

## What's in this file

- **Format:** JSON Lines (`.jsonl`) — one JSON object per line, no trailing commas or wrapping array.
- **Records:** 150
- **Duration:** ~150 seconds of simulated data, 1 record/second
- **Nodes:** A, B (sensor nodes), C (Bridge node, also has its own sensors)

## Scenario in this file

This run simulates a **subsidence precursor event**:

| Phase | Time range | What happens |
|---|---|---|
| Normal | t = 0s – ~75s | All 3 nodes read stable baseline values with small realistic sensor noise |
| Precursor drift | t = ~75s – 150s | **Node A's tilt accelerates** (0.28° → 1.13° by the end) and its **RSSI weakens** (~‑52 → ‑63), simulating physical displacement. Nodes B and C stay stable throughout as the control/reference. |

Note: the crack sensor (`crack_ok`) does **not** trip in this particular file — it stays `true` for all nodes across all 150 records. If you need a run that includes a crack-trip event, use `generate_synthetic_data.py` with `--crack-trip-frac` set (see below), or ask for a regenerated file.

The tilt drift is **accelerating (quadratic), not a step change** — this is intentional. It mirrors the real detection logic: rate-of-change matters more than absolute tilt value, since a node could sit at a naturally tilted resting angle with zero actual risk.

## Record structure

Each line matches the **Gateway → Backend** payload contract exactly (Section 9.3 of the project blueprint):

```json
{
  "gateway_id": "GW1",
  "buffered": false,
  "received_ts": 1787813002,
  "payload": {
    "bridge_id": "C",
    "ts": 1787813001,
    "nodes": [
      {
        "node_id": "A",
        "ts": 1787813001,
        "tilt_x": 0.284,
        "tilt_y": -0.005,
        "vib_rms": 0.053,
        "flex_raw": 2100,
        "crack_ok": true,
        "rssi": -50.8
      },
      { "node_id": "B", "...": "same fields" },
      { "node_id": "C", "...": "same fields, rssi is always null for C (it's the Bridge itself)" }
    ]
  }
}
```

### Field reference

| Field | Type | Meaning |
|---|---|---|
| `gateway_id` | string | Fixed at `"GW1"` for this dataset |
| `buffered` | bool | `true` would mean the record came from the Gateway's offline SD-card queue; always `false` here |
| `received_ts` | int | Unix timestamp (s) — when the Gateway received the packet |
| `payload.bridge_id` | string | Always `"C"` — Node C doubles as the Bridge |
| `payload.ts` | int | Unix timestamp (s) — when the Bridge sent the packet |
| `nodes[].node_id` | string | `"A"`, `"B"`, or `"C"` |
| `nodes[].tilt_x` / `tilt_y` | float | Tilt angle, degrees |
| `nodes[].vib_rms` | float | Vibration magnitude, m/s² |
| `nodes[].flex_raw` | int | Raw ADC reading, 0–4095 |
| `nodes[].crack_ok` | bool | `true` = copper trace intact, `false` = broken/tripped |
| `nodes[].rssi` | float or null | Signal strength the Bridge measured **from** that node (relative-distance signal). Always `null` for node C. |



## Regenerating or customizing

Use `generate_synthetic_data.py` in this repo:

```bash
python generate_synthetic_data.py --mode both --duration 150 --precursor-node A --out synthetic_data.jsonl
```

| Flag | Default | Purpose |
|---|---|---|
| `--mode` | `both` | `normal` = stable only, `precursor` = drift only, `both` = normal period then drift |
| `--duration` | `150` | Total seconds of data |
| `--precursor-node` | `A` | Which node drifts (`A` or `B`) |
| `--precursor-start-frac` | `0.5` | Fraction of duration at which drift begins |
| `--crack-trip-frac` | `0.85` | Fraction of duration at which the crack sensor trips (use `-1` to disable) |
| `--out` | `synthetic_data.jsonl` | Output filename |

In a Jupyter notebook, call the function directly instead of the CLI:

```python
from generate_synthetic_data import generate
generate(mode="both", duration=150, precursor_node="A",
         precursor_start_frac=0.5, crack_trip_frac=0.85,
         out_path="synthetic_data.jsonl")
```

## Known limitations

- Timestamps are wall-clock at generation time, not fixed — regenerating produces a new time range each run. If the team needs a reproducible dataset with fixed timestamps/seed, flag it so the generator can be extended.
- This is synthetic noise, not captured from real MPU6050/flex/crack hardware — anomaly thresholds tuned here **must be re-validated against real sensor noise** in Phase 5 (per the project blueprint's Section 7 risk log).
